# Skill maintenance scenarios

Use these small cases when changing routing or operating guidance. Review the
selected owner, requested effects, produced result, and completion claim.
For an independent evaluation, provide the request and minimal inputs first;
keep expected outcomes below out of the evaluating agent's initial context.
Do not execute against personal data or a live instance for these cases.

| Request and synthetic inputs | Expected outcome |
| --- | --- |
| Correct a documentation link with a clean owning source reference | Route through the developer handbook and regression planner; fix the link and use scoped documentation checks. No runtime or publication claim. |
| Explain why a generic MCP client sees no tools; supply a catalog and an existing restricted policy | Diagnose the permission projection before proposing a key. No packaged-client allowlist requirement or automatic permission expansion. |
| Issue a key for a specified node, policy, expiry, and private destination using synthetic HTTP responses | Preserve the selected policy, deliver the credential privately, and report safe status. No default organization publication. |
| Plan an offline archive from an installed skill and an explicit fixture repository | Resolve skill resources separately from project files. Dry-run succeeds without invoking a builder or producing an archive. |
| Change one repository-local Plugin or Service with its README and package definition | Select the local implementation owner and its focused verifier. A catalog-only sibling supplies no implementation authority. |
| Connect Kimi CLI or configure current Antigravity using an explicit active configuration path | Select the actual MCP adapter identity and configured destination. Make no desktop-history or conversation-control qualification claim. |

Executable helper and distribution tests cover deterministic mechanics.
Reviewing this table alone is not evidence of independent model evaluation.
