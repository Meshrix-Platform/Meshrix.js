# Meshrix.js Status

Status assessed on 2026-08-16.

This document owns current product status. It separates intent,
implementation, verification, release, and support. Source, a Plan, a command,
a prior report, or a changelog entry cannot satisfy a different dimension by
itself.

## Product-wide status

| Dimension | Current status |
| --- | --- |
| **Intent** | The only current Plan is one enterprise single-node functional candidate whose Agent MCP path is always downstream MCP → downstream Gateway → optional application stage → upstream Gateway → upstream Service. Every downstream operation declares immutable `trafficModel: workspace_application | gateway_transit`; this field selects only whether the middle Workspace application stage runs and never bypasses either Gateway. The downstream and upstream Gateways each have one built-in channel and optional External Gateway choices, selected independently by explicit Console action. Both traffic models must receive the selected Gateway's bounded load distribution, rate and concurrency admission, health and circuit handling, overload degradation, timeout, cancellation, streaming, and backpressure. External Gateway owns neither application-stage choice, Workspace, Meshrix semantics nor route selection. Plugin activation changes availability only. The candidate also includes one independently deployable Model Gateway HTTP Service, a default-disabled stateless Meshrix adapter, a one-way local Agent self-maintenance plugin, and plugin confinement. Engineering is not complete. |
| **Implementation** | Server, Console, Operation Permission, Workspace collaboration, storage, jobs, Plugin Host, the embedded Agent Gateway, Meshrix downstream MCP and upstream-Service paths, the current nested generic External Gateway profile-management implementation, Core-owned Maintenance Agent, and their public surfaces exist. The upstream gateway already implements governed traffic controls, but the current MCP execution path unconditionally calls `resolveMcpWorkspaceInput` before ordinary tool execution and does not provide one proven mandatory downstream-Gateway / optional-application / upstream-Gateway pipeline. External Gateway does not yet contribute selectable Runtime Plugin channels for both traffic models. The standalone Model Gateway Service, optional adapter, `AgentMcpGatewayPipeline`, `DownstreamGatewayEnvelope`, `UpstreamGatewayEnvelope`, Core per-direction selectors, Console switching, External Gateway Runtime Plugin, independent local maintenance plugin, and complete removal of old assumptions and authorities remain GATE work. |
| **Verification** | The retained efficiency baseline covers the optional Workspace application stage and must not be interpreted as direct-transit or Gateway-production-control evidence. Independent Service direct operation, complete trafficModel coverage and caller non-override, mandatory downstream-then-upstream Gateway traversal for both traffic models, Workspace application efficiency between those stages, direct transit with zero Workspace calls or state effects, missing-classification denial before any stage, built-in/plugin semantic equivalence for both modes, load and degradation controls at both Gateway stages, plugin activation with zero traffic change, explicit Console-controlled per-direction switching, dual-generation drain, no implicit fallback or stage bypass, local maintenance directionality, plugin confinement, and Console isolation still require GATE evidence. Project-level `npm run verify:acceptance` has not run. Historical Plan receipts are not current evidence. |
| **Release** | `0.0.1` remains the declared target. Meshrix `runtime-ui` retains one public origin and does not embed the Model Gateway Service or a second backend port. The Service requires its own independently built OCI artifact and evidence. Tag, package set, OCI manifests, GitHub Release, and hosted deployment require immutable same-candidate channel evidence after GATE-FINAL. |
| **Support** | Native-host, client, cloud, cross-host, and recovery qualification remain FutureGoals after this candidate. Linux VM delivery is required for the current plan's offline and plan-receipt closures. |
